01 // ProblemNo labels, many readings

Which unusual reading is worth checking?

No labelsThe data does not tell us which readings are real problems.
More than limitsA reading can be unusual for its own point even when it is within a fixed limit. Applicable historical limits are not available to verify missed alerts.
Review takes timeEvery unnecessary investigation costs an operator attention and time.

Each point is judged only against its own last 28 days.No comparison between plants

02 // End-to-end pipelineHistorical, day-level data

From measurements to review.

01 // INPUT

Prepare

Preserve original records and source information. Select six exploratory groups: influent volume, oxygen, ammonium, nitrate, suspended solids and temperature.

02 // DETECT

Score

Compare each point with its own history and apply simple data-quality rules.

03 // ORGANISE

Group

The history detector groups nearby flagged days into cases and ranks them within each plant.

04 // REVIEW

Investigate

A local dashboard shows stored AI flags, historical evidence and a review budget. The operator decides what to check.

Six group-specific forests offer a second ranking; the history detector also works on its own.In parallel · experimental AI

03 // History detectorEach point keeps its own history

Learn what is usual here.

01 // BASELINE

Look back

Use the previous 28 calendar days, excluding today, with at least 14 valid days. Calculate the median and robust spread.

02 // EVIDENCE

Check today

Measure deviation from the baseline. Flag stuck values and unexpected zeros; negative checks exclude temperature.

03 // OUTPUT

Form cases

Group nearby flagged days. Rank by rule hits, duration and peak score; preserve reasons and source references.

Missing, duplicate or insufficient history can leave a reading unscored; unscored is not normal.Safeguard

Scrub through a synthetic series to see the score →

Thresholds are calibrated per series. The approximately 1% target flag rate is a workload assumption, not a measured false-alarm rate.

04 // Experimental AI layerNo peer comparison

Spot an unusual combination.

01 // FEATURES

Six signals

Deviation, daily change, recent deviation, relative level, zero and repeated days.

02 // MODEL

Six forests

One Isolation Forest per measurement group looks for uncommon combinations of history-based features.

03 // ROLE

Second view

Compare its reading-level ranking with the independent history detector. Scores stay within each group.

A higher score means a rarer feature pattern, not a fault probability or diagnosis.Interpretation

06 // Operator decisionEvidence, not a diagnosis

Check what matters first.

01

See

Review stored AI flags for one plant and measurement in a local dashboard.

02

Understand

Inspect the reading, its 28-day history, historical median and source context.

03

Prioritise

Set a review budget and keep deferred cases visible for the selected metric.

04

Decide

The operator investigates. Review decisions are not yet saved between sessions.

The dashboard reads precomputed results; it does not run the models live. It supports English and Dutch and can optionally ask Claude to explain a stored reading; it works without it.

08 // Get startedOpen source, runs locally

Run it on your own data.

Second Opinion reads a Z-info table export of daily measurements. No data ships with the repository: measurement data, scores and fitted models stay on your machine. Every example on this site is synthetic, and the pipeline can run on a fully simulated export. Use Python 3.11.

git clone https://github.com/Second-Opinion-Dev/Second_Opinion.git
cd Second_Opinion
python -m pip install -r requirements.txt
# place the export under data/tai/extracted/, then:
python src/pipeline.py --plan      # show what would run
python src/pipeline.py             # full run
