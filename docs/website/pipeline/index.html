How the pipeline works

Follow a reading through every stage.

Each stage below runs in your browser on a small, seeded synthetic example, using simplified versions of the real code. The numbers show how each stage works. They are not results from any plant.

01 // PrepareKeep every row

Add context, never remove it.

Preparation reads the Z-info export and keeps every row with its source file and row number. Problems are flagged for review, never deleted, filled in, averaged or converted. Click a row to see what happens to it.

02 // ScoreEach point keeps its own history

Compare today with its own last 28 days.

For each day, the detector takes the previous 28 calendar days of the same series (never today, never another plant), with at least 14 valid days. The score is the distance from the prior median, in robust spreads. Drag across the chart or use the sliders.

03 // RulesData-quality checks alongside the score

Catch what a score cannot see.

Three simple rules run next to the score: stuck (the same value on 7 or more days after a history that varied), dropout (a zero after a window without zeros) and negative. Inject an artificial fault, as the project's fault evaluation does, and switch the rules off to compare.

04 // CasesRanked within one plant

Turn flagged days into a review order.

Flagged days of one series become one case when at most one unflagged day separates them. Cases are ranked within the plant: rule hits first, then more flagged days, then a higher peak score. This is a documented review order, not a severity. Click a day to cycle it through not flagged, score flag and rule hit.

05 // Second viewExperimental Isolation Forest

Unusual combinations isolate quickly.

The forest splits the data at random. A rare combination of features ends up alone after only a few splits; a typical one takes many. Averaged over 100 trees, fewer splits give a higher ai_score. That means rarer, not faulty. Click any point to isolate it.

06 // EvaluateChronological, no labels

Set the bar on one year, test it on the next.

The forest trains on data through 2023. The alert threshold is set on 2024 validation scores (the 99th percentile by default), then frozen and applied to the held-out 2025. Move the percentile to see how the threshold and workload shift.
